# 生成月报

当用户说"生成月报"、"上月月报"或要求生成月报时，自动执行以下流程。

## 执行步骤

### 1. 确定月份

- **月报覆盖一个自然月：1日到月末**（如7月报为7月1日到7月31日）
- 月份格式：`YYYY-MM`（如 `2026-07`）

#### 1.1 参数解析规则

**无参数时（默认逻辑）：**
- 如果当前日期在10日及以前（day <= 10），自动生成上月月报
- 如果当前日期在10日以后，提示用户选择：生成上月还是本月月报
- 示例：今天是8月5日 → 自动生成7月月报；今天是8月15日 → 提示选择

**有参数时：**
根据用户传入的参数确定月份或日期范围：

| 参数 | 含义 | 月份/日期范围 |
|------|------|---------------|
| `本月` | 本月月报 | 当前月1日到月末 |
| `上月` | 上月月报 | 上月1日到月末 |
| `X月`（如`7月`、`8月`） | 指定月份月报 | 该月1日到月末 |
| `X月X日到Y月Y日`（如`7月15日到8月15日`、`3月10日到24日`） | 自定义日期范围月报 | 起始日到结束日（>14天视为月报） |
| `一季度` | 第一季度月报 | 1月1日到3月31日 |
| `二季度` | 第二季度月报 | 4月1日到6月30日 |
| `三季度` | 第三季度月报 | 7月1日到9月30日 |
| `四季度` | 第四季度月报 | 10月1日到12月31日 |

- 参数含"月"或"季度"关键字 → 按月报处理
- 自定义日期范围：天数 >14 → 月报，≤14 → 周报
- 未指定年份默认当前年；月份大于当前月则视为去年
- 自定义日期范围月报时，使用日期范围参数调用脚本（见下方3.2节）

#### 1.2 示例
- 今天是2026年8月15日，无参数 → 提示选择上月(7月)或本月(8月)
- 今天是2026年8月5日，无参数 → 自动生成上月月报(7月)
- 参数"7月" → 生成2026年7月月报
- 参数"7月15日到8月15日" → 生成2026/07/15到2026/08/15的月报
- 参数"一季度" → 生成2026年1月1日到3月31日的月报

### 2. 提取数据

运行参数化提取脚本（位于本技能目录下）：

**按月份提取：**
```bash
python "<技能目录>/extract_month.py" <YYYY-MM> <output_path>
```
示例：
```bash
python "C:\Users\HONOR\.trae-cn\skills\generate-monthly-report\extract_month.py" 2026-07 "C:\Users\HONOR\.trae-cn\skills\generate-monthly-report\month_data.json"
```

**按自定义日期范围提取（跨月场景如"7月15日到8月15日"）：**
```bash
python "<技能目录>/extract_month.py" <YYYY-MM-DD> <YYYY-MM-DD> <output_path>
```
示例：
```bash
python "C:\Users\HONOR\.trae-cn\skills\generate-monthly-report\extract_month.py" 2026-07-15 2026-08-15 "C:\Users\HONOR\.trae-cn\skills\generate-monthly-report\month_data.json"
```

**⚠️ 人员完整性校验**：脚本运行后检查输出，如果出现 `WARNING: Found unmapped persons!`：
1. 根据输出的 uid，在 `extract_month.py` 的 `USER_MAP` 中添加映射（格式：`uid → "岗位 姓名"`）
2. 重新运行提取脚本
3. **不得带着警告直接生成报告**

### 3. 生成 Word 文档

确保 `docx` npm 包可用（首次使用时运行 `npm install docx`），然后执行：

**按月份生成：**
```bash
node "<技能目录>/gen_month_docx.js" <start_YYYY-MM-DD> <end_YYYY-MM-DD> <data_file>
```
示例：
```bash
node "C:\Users\HONOR\.trae-cn\skills\generate-monthly-report\gen_month_docx.js" 2026-07-01 2026-07-31 "C:\Users\HONOR\.trae-cn\skills\generate-monthly-report\month_data.json"
```

**按自定义日期范围生成（跨月场景如"7月15日到8月15日"）：**
```bash
node "<技能目录>/gen_month_docx.js" <start_YYYY-MM-DD> <end_YYYY-MM-DD> <data_file>
```
示例：
```bash
node "C:\Users\HONOR\.trae-cn\skills\generate-monthly-report\gen_month_docx.js" 2026-07-15 2026-08-15 "C:\Users\HONOR\.trae-cn\skills\generate-monthly-report\month_data.json"
```

- 生成脚本内置日期范围过滤，即使数据文件包含范围外的记录也只统计目标范围
- 输出文件自动保存到：`D:\华为家庭存储\工作文档\TIU管理\周报月报\` 目录下

### 4. 完成后

告知用户报告已生成，附上文件链接，并简要列出数据概览（记录数、总工时、工作日数、参与人数、涉及项目数）。

## 关键规则

### 人员映射
- FlowUs "人员"字段是 formula 类型，API 返回 null，无法直接读取
- 通过记录的 `created_by.id`（uid）配合 `USER_MAP` 映射到"岗位 姓名"
- USER_MAP 中的完整映射参考 `extract_month.py` 中的注释
- 添加新成员时：在 USER_MAP 中添加 `uid → "岗位 姓名"`

### 报告结构
1. **封面**（纵向）：标题"项目月报（YYYY年M月）" + 实际数据日期范围 + 统计概览表
2. **一、人员投入统计**：表格（显示"岗位 姓名"，列含"填报天数"）
3. **二、项目投入统计**：表格（参与人员列只显示姓名，不显示岗位）
- 一、二表"投入工时"列：表头为"投入工时（人天）"，数据格式"小时数（人天数）"，人天数=小时数/8四舍五入1位小数，整数不显示.0
4. **三、人员×项目投入矩阵（工时）**：横向表格（显示"岗位 姓名"，人员列宽14%）
5. **四、项目月度工作总结**（先项目）：按项目汇总所有人员工作，简化为类别名称（不列明细），"其他运维相关工作"和"其他相关工作"合并为"运维及其他工作"
6. **五、人员月度工作总结**（后人员）：按人员+项目汇总整月工作（详细）
- 项目排序：非HD项目排末尾，其余按工时降序
- 项目总结是人员总结的**严格子集**（从人员总结输出反向汇总，保证两边条目一致）

### 工作总结格式
- 人员名显示蓝色（color: 0066CC），加粗，字号22（比项目名大一号）
- 项目名黑色加粗，缩进120；工作条目缩进480，层级清晰
- 项目名后显示工时和天数，然后换行显示工作描述
- 人员总结行格式：`岗位 姓名  工时数工时（合计X人天），总共填报X次`（人天数=工时/8，整数不显示.0）
- 项目总结行格式：`项目名  工时数工时（合计X人天），X人参与（人员列表）`
- 项目内工作行格式：`项目名  工时数工时（合计X人天），填报X次`
- 工作描述带序号（1, 2, 3...），每人序号独立从1开始
- 优先从进展说明提取工作内容，过滤纯进度状态（如`100%`、`（未开发）`），仅最后一天保留百分比
- 进展说明过短（<6字）时，结合任务名称显示为"任务名称+进展内容"（无冒号）
- 进展说明不存在时，回退到任务名称字段
- 冒号处理（removeColons）：短前缀（≤4字）直接去掉冒号，长前缀替换为逗号
- 平凡任务过滤（filterTrivialTasks）：过滤"提交脚本/提交代码"类条目（始终生效）
- 运维预处理（preprocessMaintenanceTasks）："处理"开头的条目归入"运维及其他工作"，不逐条列出
- 前缀合并（mergeByPrefix）：共享4+字前缀的条目合并为概括名称（如"沟通功能开发"+"沟通功能调整"→"沟通功能优化"）
- 成对组合并（mergePairedGroups）：已分组的条目共享2+字前缀时合并
- 同类合并（mergeByCategory）：同类别条目≥3项时合并（如3+文档类→"编写说明文档"，3+问题类→"问题处理相关工作"，3+操作指引→"操作指引沟通"）
- 去重合并（mergeSimilarItems）：前缀匹配≥5字、包含关系、或字符级Jaccard相似度≥0.7（跳过已是主题组的条目避免误合并）
- 主题分组（groupThemes）：3+项共享≥2字前缀时全部合并为一个摘要，超5项取最短5项；按任务性质自动判定后缀（功能开发/相关问题处理/功能开发及相关问题处理）
- 后缀合并（combineSuffix）：避免"XX相关相关问题处理"式重复（后缀已含"相关"时不再加）
- 前缀重命名："生产"/"生产环境"→"其他运维"，"处理"→"其他"（避免过于笼统的分组名）
- 统一简化（simplifySummary）："问题处理相关工作/其他运维相关工作/其他相关工作"→"运维及其他工作"；相关主题组合并（mergeRelatedGroups）；"运维及其他工作"吸收同类子类别（mergeSubCategories）并排到最后；"生产环境/生产运维相关问题处理"合并为"运维相关问题处理"
- 条目过多时：>15条只留主题组和类别标签；>8条先按多天保留（dropSecondaryTasks 删除部署/熟悉/初始化等次要任务）
- 分类排序（sortByCategory/classifyWork）：按 功能开发→问题处理→文档→运维→需求沟通→售前→其他 排序，主题组排前，"运维及其他工作"永远最后
- 排版格式化（formatWorkItems）：按类别排序后编号
- 不列出每日任务标签，因为任务标签加起来不等于总工时
- 跨月时标题为纯"项目月报"（无括号日期），单月时为"项目月报（YYYY年M月）"

### 页面布局
- 封面Section：纵向（Portrait）
- 正文Section：横向（Landscape），尺寸 16838×11906 DXA，margin 720
- 封面概览表宽度：6000 DXA
- 一、二表宽度：9000 DXA
- 三矩阵表宽度：100% PERCENTAGE（不用DXA，不用FIXED）
  - 人员列：14%，合计列：8%，项目列：Math.floor((100-14-8)/项目数)%
