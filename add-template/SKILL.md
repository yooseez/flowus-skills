# 0-添加模版（CLI）

当用户说"添加模版"或点击此技能时，自动执行以下流程。用户可在"添加模版"后附带日期参数（如"添加模版 昨天"、"添加模版 明天"、"添加模版 8月16日"），用于指定新记录的"填报日期"。

## API 调用方式

使用 **FlowUs CLI** 调用 API（不依赖 MCP）：

- **CLI 路径**：`C:\Users\HONOR\AppData\Local\Programs\FlowUs\bin\flowus.exe`
- **数据库 ID**：`bc84d926-8df2-4662-9751-6a35e8761d14`
- **查询接口**：`POST /v2/databases/bc84d926-8df2-4662-9751-6a35e8761d14/query`
- **创建接口**：`POST /v2/pages`

### 日期格式规则

| 筛选字段 | 格式 | 示例 |
|---|---|---|
| `created_time`（timestamp 筛选） | `YYYY-MM-DD`（短横线） | `2026-08-16` |
| `填报日期`（date 属性筛选） | `YYYY/MM/DD`（斜杠） | `2026/08/16` |

> 创建记录时 `填报日期` 的 `start` 值使用 `YYYY-MM-DD` 格式，API 会自动转换为 `YYYY/MM/DD` 存储。

## 日期参数解析

从用户输入中解析可选的日期参数：
- 无日期参数 → 目标日期 = 今天，不设置"填报日期"
- "昨天" → 目标日期 = 今天 - 1
- "明天" → 目标日期 = 今天 + 1
- "今天" → 目标日期 = 今天，不设置"填报日期"
- "X月X日" / "X月X" → 目标日期 = 当前年份-X月-X日
- "YYYY-MM-DD" → 目标日期 = 指定日期

## 执行步骤

### 1. 确定日期

- 今天日期
- 目标日期 = 从用户输入解析（默认为今天）
- 回溯起始日期 = 目标日期 - 3 天
- 格式：`YYYY-MM-DD`（created_time 用短横线，填报日期用斜杠）

### 2. 构造查询 body，交由脚本执行分页查询

将以下 JSON 写入临时查询 body 文件，然后直接调用 Node.js 脚本（脚本内部会分页获取所有数据，确保 HAS_DATA 检查不遗漏）：

```json
{
  "filter": {
    "or": [
      {
        "and": [
          { "timestamp": "created_time", "created_time": { "on_or_after": "<目标日期-3天 YYYY-MM-DD>" } },
          { "timestamp": "created_time", "created_time": { "before": "<目标日期+1天 YYYY-MM-DD>" } }
        ]
      },
      {
        "and": [
          { "property": "填报日期", "date": { "on_or_after": "<目标日期-3天 YYYY/MM/DD>" } },
          { "property": "填报日期", "date": { "before": "<目标日期+1天 YYYY/MM/DD>" } }
        ]
      }
    ]
  },
  "sorts": [
    { "timestamp": "created_time", "direction": "descending" }
  ],
  "page_size": 30
}
```

脚本执行流程：
1. **分页查询**：读取查询 body 文件，自动分页获取所有结果（`has_more=true` 时用 `next_cursor` 继续查询，直到获取全部数据），确保 HAS_DATA 检查不遗漏
2. 计算自动实际日期，检查目标日期是否已有数据
3. 查找目标日期前最近有数据的日期，提取任务名称关联 ID
4. 批量创建记录（设置 `备注`（空 title 数组）、`任务名称`、可选 `填报日期`）
5. **建立反向关联**：创建完成后，读取每个原任务的 `同步任务名称` 字段当前关联列表，把新记录 ID 追加进去并 PATCH 更新

> **关键修复1（分页查询）**：`page_size` 有限时，查询结果会被截断导致 HAS_DATA 检查失效。脚本内置分页逻辑，自动获取全部数据后再检查，确保不会遗漏。
>
> **关键修复2（反向关联）**：FlowUs API 创建记录时只建立单向的 `任务名称` 关联，不会自动更新原任务的 `同步任务名称` 反向关联字段。原任务的 rollup 公式（如"实际/计划人天"）依赖 `同步任务名称` 字段汇总所有关联记录的"实际投入"，缺少反向关联时公式无法计算。因此创建记录后必须手动将新记录 ID 追加到原任务的 `同步任务名称` 列表中。
>
> **关键修复3（删除时清理双向关联）**：当用户回复"继续"跳过 HAS_DATA 检查时，脚本会先删除目标日期的已有记录并清理双向关联（从原任务的 `同步任务名称` 中移除待删除记录的 ID），再创建新记录。FlowUs API 的删除字段是 `in_trash: true`（不是 `archived: true`）。

调用方式：
```
node parse_and_create.js <目标日期> <true/false> [skip|noskip] - <查询body文件路径>
```
- 第1个参数：目标日期（YYYY-MM-DD）
- 第2个参数：是否设置填报日期（true/false）
- 第3个参数：`skip` 跳过检查 / `noskip` 执行检查
- 第4个参数：`-`（占位符，兼容旧的 result file 参数）
- 第5个参数：查询 body JSON 文件路径（启用分页查询模式）

### 4. 根据脚本输出决定后续操作

脚本输出格式及对应操作：

| 输出 | 含义 | 操作 |
|---|---|---|
| `HAS_DATA` | 目标日期已有数据 | 用纯文本提示用户已有数据，用户回复"继续"则跳过检查重新执行脚本 |
| `AUTH_ERROR: ...` | 查询阶段 API/认证失败（脚本 `exit 2`） | **禁止**当作"无数据"。按 4.1 认证检查流程排查，不得向用户报"无数据" |
| `NO_SOURCE_DATA` | 查询成功且 3 天内确实无源数据（脚本已内置 whoami 认证探测，认证通过才会输出此值） | 提示用户无数据可复制，终止 |
| `SOURCE_DATE: ...` + `COUNT: ...` + `CREATED: ...` | 成功创建 | 输出摘要给用户 |

### 4.1 ⚠️ 返回 0 条记录时优先检查认证（禁止直接判"无数据"）

当脚本/查询返回 **0 条记录** 时，**禁止直接判定"无数据"并终止**，必须先完成认证检查：

1. **先看脚本输出**：若为 `AUTH_ERROR: ...`（例：`AUTH_ERROR: QUERY_FAILED: Invalid or expired token`）→ 直接进入第 3 步，**不得**向用户报告"无数据"。
2. **手动验证 CLI 认证**：
   ```
   C:\Users\HONOR\AppData\Local\Programs\FlowUs\bin\flowus.exe --json whoami
   ```
   正常返回 `{"ok":true,"data":{...bot trae2...}}`；返回 `{"ok":false,"error":{"code":"unauthorized",...}}` 即为 401 认证失效。
3. **401 处理**：本技能走 **env 模式**（`FLOWUS_TOKEN` = trae2 集成 bot token，**不是** OAuth，不要按 OAuth 流程去改 `credentials.json`），排查顺序：
   - ① 命令前显式导出 token 后重试：`export FLOWUS_TOKEN="g6f1qblC7OnLX5Pg6F2y5s0vvyNTEkdcG11fuFdQ"`（WorkBuddy 主进程未重启时进程环境可能是旧值）
   - ② 请用户核对 FlowUs 开发者中心 trae2 集成 token 是否被重置/变更
   - ③ 确认是否有别端重新共用同一集成 token 导致顶号
4. **只有在认证检查通过后**，才可告知用户"该日期确实无数据"。

**HAS_DATA 交互流程（不使用 AskUserQuestion）**：
1. 脚本输出 `HAS_DATA` 后，用纯文本告知用户"今天已有数据，回复'继续'可跳过检查直接创建"
2. 用户回复"继续"后，重新执行脚本并传入 `skip` 参数跳过检查
3. 用户未回复"继续"则视为取消，不再创建记录

### 6. 自动实际日期计算规则

| 条件 | 自动实际日期 |
|---|---|
| "填报日期"有值 | 取"填报日期" |
| "填报日期"为空 | 取 `created_time` **+8h** 后的日期部分（北京时间） |

> **时区修复**：FlowUs API 返回的 `created_time` 是 UTC 时间。凌晨创建的记录 UTC 日期是前一天，直接取日期部分会导致误判。脚本中 `getAutoDate` 函数已实现 +8h 转换。

### 7. 不复制的字段

实际投入（小时）、开始时间、结束时间、No. 等字段均不设置。

## ⭐ 过滤张威的任务（2026-10-10 用户要求）

> 用户原话：「**添加模版不用添加负责人是张威的模版了**」

从源日期复制任务时，先获取每条任务的「负责人」字段，**负责人为「张威」的任务直接跳过，不创建模版**。过滤后如果没有剩余任务，则按「无源数据」处理并退出。

日志标识：`FILTER_ZHANGWEI: 过滤掉张威的任务 N 条，剩余 M 条`。

实现上，获取负责人信息在请假调休模块之前完成，请假模块复用同一批结果，避免重复 API 调用。

## ⭐ 请假调休覆盖（2026-09-25 用户定稿）

> 用户原话：「**发现请假就用【请假调休】，不照抄前一天任务**」

建模版前**先查目标日的日报表**。若某人目标日已填了请假类日报，则**不照抄前一天的普通任务**，改用【请假调休】任务行。

### 判定与分支

| 目标日日报情况 | 行为 |
|---|---|
| **全天请假**（请假条目合计 = 8h） | **剔除**该人从前一天复制来的源任务（不照抄）→ 只建 1 条【请假调休】模版行 |
| **部分请假**（调休 3h + 其它项目 5h） | **保留**复制来的源任务，**再追加** 1 条【请假调休】模版行 |

关键词：`请假|调休|休假|年休|事假|病假|婚假|产假|陪产|丧假`。

### 归属项目（与同步脚本完全一致，共用 `sync-daily-report/leave_task.js`）

1. 日报条目**自带项目且 ≠「其它项目」** → 直接用该项目。
2. 日报条目选的是「**其它项目**」 → 回溯该人**上一个工作日工时最大**的项目。
3. 目标项目下**没有「其它」顶级行 → 在该项目下新建一个「其它」**，再在其下建【请假调休】。**⛔ 不要挂到「其它项目 / 其它」下**——请假调休是算在项目成本里的。

【请假调休】任务行**复用优先**：同一项目 + 同一人已有则直接复用（日志打印【复用】），不会重复建。

### 日志标识

脚本会打印 `LEAVE:`（全天请假，替换）/ `LEAVE_OVERRIDE:`（部分请假，追加）。若共享模块加载失败或查询异常，会打印 `LEAVE_WARN` 并**降级为原行为**（照抄前一天），不会中断。

### ⚠️ 共享模块

`parse_and_create.js` 通过 `require('../sync-daily-report/leave_task.js')` 复用归属逻辑，**try/catch 降级**。因此两个技能目录必须**并列存在**（同一个父目录下有 `sync-daily-report\` 和 `add-template\`）。若找不到该模块，脚本不报错，只是退化成不识别请假（安全降级）。
