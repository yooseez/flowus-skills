# 添加模版

当用户说"添加模版"或点击此技能时，自动执行以下流程。用户可在"添加模版"后附带日期参数（如"添加模版 昨天"、"添加模版 明天"、"添加模版 8月16日"），用于指定新记录的"填报日期"。

## API 调用方式

使用 **FlowUs CLI** 调用 API（不依赖 MCP）：

- **CLI 路径**：`C:\Users\HONOR\AppData\Local\Programs\FlowUs\bin\flowus.exe`
- **数据库 ID**：`bc84d926-8df2-4662-9751-6a35e8761d14`
- **查询接口**：`POST /v2/databases/bc84d926-8df2-4662-9751-6a35e8761d14/query`
- **创建接口**：`POST /v2/pages`

### 日期格式规则

| 筛选字段 | 格式 | 示例 |
|---|---|---|
| `created_time`（timestamp 筛选） | `YYYY-MM-DD`（短横线） | `2026-08-16` |
| `填报日期`（date 属性筛选） | `YYYY/MM/DD`（斜杠） | `2026/08/16` |

> 创建记录时 `填报日期` 的 `start` 值使用 `YYYY-MM-DD` 格式，API 会自动转换为 `YYYY/MM/DD` 存储。

## 日期参数解析

从用户输入中解析可选的日期参数：
- 无日期参数 → 目标日期 = 今天，不设置"填报日期"
- "昨天" → 目标日期 = 今天 - 1
- "明天" → 目标日期 = 今天 + 1
- "今天" → 目标日期 = 今天，不设置"填报日期"
- "X月X日" / "X月X" → 目标日期 = 当前年份-X月-X日
- "YYYY-MM-DD" → 目标日期 = 指定日期

## 执行步骤（优化版，减少积分消耗）

### 1. 确定日期

- 今天日期
- 目标日期 = 从用户输入解析（默认为今天）
- 回溯起始日期 = 目标日期 - 3 天
- 格式：`YYYY-MM-DD`（created_time 用短横线，填报日期用斜杠）

### 2. 合并查询：检查目标日期 + 查找源数据（单次 API 调用）

一次查询覆盖 `[目标日期-3天, 目标日期+1天)` 范围，同时完成：
- 检查目标日期是否已有数据
- 查找目标日期前最近有数据的日期

将以下 JSON 写入临时文件后调用 CLI：

```json
{
  "filter": {
    "or": [
      {
        "and": [
          { "timestamp": "created_time", "created_time": { "on_or_after": "<目标日期-3天 YYYY-MM-DD>" } },
          { "timestamp": "created_time", "created_time": { "before": "<目标日期+1天 YYYY-MM-DD>" } }
        ]
      },
      {
        "and": [
          { "property": "填报日期", "date": { "on_or_after": "<目标日期-3天 YYYY/MM/DD>" } },
          { "property": "填报日期", "date": { "before": "<目标日期+1天 YYYY/MM/DD>" } }
        ]
      }
    ]
  },
  "sorts": [
    { "timestamp": "created_time", "direction": "descending" }
  ],
  "page_size": 30
}
```

### 3. 用 Node.js 脚本解析查询结果

将查询结果保存到临时文件，然后用 Node.js 脚本一次性完成所有解析逻辑，只输出精简结果：

脚本路径：`.trae/skills/add-template/parse_and_create.js`

脚本执行流程：
1. 读取查询结果文件，解析记录
2. 计算自动实际日期，检查目标日期是否已有数据
3. 查找目标日期前最近有数据的日期，提取任务名称关联 ID
4. 批量创建记录（设置 `备注`（空 title 数组）、`任务名称`、可选 `填报日期`）
5. **建立反向关联**：创建完成后，读取每个原任务的 `同步任务名称` 字段当前关联列表，把新记录 ID 追加进去并 PATCH 更新

> **关键修复**：FlowUs API 创建记录时只建立单向的 `任务名称` 关联，不会自动更新原任务的 `同步任务名称` 反向关联字段。原任务的 rollup 公式（如"实际/计划人天"）依赖 `同步任务名称` 字段汇总所有关联记录的"实际投入"，缺少反向关联时公式无法计算。因此创建记录后必须手动将新记录 ID 追加到原任务的 `同步任务名称` 列表中。

调用方式：
1. 将查询结果保存到临时文件（如 `flowus_query_result.log`）
2. 执行：`node parse_and_create.js <目标日期> <true/false> [skip|noskip] <查询结果文件路径>`
   - `skip` 跳过目标日期已有数据检查，`noskip` 或省略则执行检查

### 4. 根据脚本输出决定后续操作

脚本输出格式及对应操作：

| 输出 | 含义 | 操作 |
|---|---|---|
| `HAS_DATA` | 目标日期已有数据 | 用纯文本提示用户已有数据，用户回复"继续"则跳过检查重新执行脚本 |
| `NO_SOURCE_DATA` | 3天内无源数据 | 提示用户无数据可复制，终止 |
| `SOURCE_DATE: ...` + `COUNT: ...` + `CREATED: ...` | 成功创建 | 输出摘要给用户 |

**HAS_DATA 交互流程（不使用 AskUserQuestion）**：
1. 脚本输出 `HAS_DATA` 后，用纯文本告知用户"今天已有数据，回复'继续'可跳过检查直接创建"
2. 用户回复"继续"后，重新执行脚本并传入 `skip` 参数跳过检查
3. 用户未回复"继续"则视为取消，不再创建记录

### 5. 自动实际日期计算规则

| 条件 | 自动实际日期 |
|---|---|
| "填报日期"有值 | 取"填报日期" |
| "填报日期"为空 | 取 `created_time`（日期部分） |

### 6. 不复制的字段

实际投入（小时）、开始时间、结束时间、No. 等字段均不设置。

## 优化说明

| 优化项 | 之前 | 优化后 |
|---|---|---|
| 查询次数 | 2 次（检查 + 源数据） | 1 次合并查询 |
| 回溯范围 | 7 天（~50 条） | 3 天（~10 条） |
| page_size | 100 | 30 |
| 创建记录 | 10 次 Shell + 10 次 Write | 1 个 Node.js 脚本批量创建 |
| 响应处理 | 完整响应进入上下文 | 只输出精简摘要 |
| 回收站检查 | 考虑 | 跳过 |
