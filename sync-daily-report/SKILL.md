# 0-同步日报

当用户说"同步日报"或点击此技能时，将指定日期日报里的工时，按"人员+项目"匹配写入到当天模版记录的"实际投入（小时）"字段。

## 日期参数解析

从用户输入解析目标日期（北京时间）：
- 无日期参数 → 目标日期 = **昨天**（默认）
- "昨天" → 今天 - 1
- "前天" → 今天 - 2
- "今天" → 今天
- "X月X日" / "X月X" → 当前年份-X月-X日（若算出的日期晚于今天，则取上一年）
- "YYYY-MM-DD" → 指定日期

## 数据模型与匹配逻辑

| 数据源 | 数据库 | 关键字段 |
|---|---|---|
| 日报库 | `1a9c4392-b5ae-48f4-aa3b-e05135215dce` | `日期`(date) + `created_by`(人员) + `项目-1/2/3`(select) + `任务工时-1/2/3`(number) |
| 模版库 | `bc84d926-8df2-4662-9751-6a35e8761d14` | `任务名称`(relation→任务页) + `实际投入（小时）`(number) |
| 任务库 | 任务页 | `负责人`(select) + `所属项目`(relation→项目页 title) |

- 匹配键：日报人员(created_by→USER_MAP) + 项目名 ↔ 模版任务负责人 + 所属项目页标题
- 项目名规范化：去 `〓` 符号 + 别名映射（`浙能法务→浙能法务二期`、`非HD项目→其它项目`）
- **排除张威**：按任务页 `负责人` 过滤（不是按模版创建者）
- 日报日期用"日期"字段；模版日期用 getAutoDate（填报日期优先，否则 created_time 转**北京时间**取日期——UTC 时区坑已修复）
- 每人日报合计不足 8 小时视为问题（排除张威）

## 执行步骤

### 1. 确定目标日期（见上节解析规则）

### 2. 运行分析脚本

```
node "C:\Users\HONOR\.workbuddy\skills\sync-daily-report\sync_report.js" <目标日期YYYY-MM-DD>
```

脚本会：查询日报和模版 → 匹配分组 → 判定模式 → 生成状态文件 `fill_state_<日期>.json`（与脚本同目录）。

**判定规则（核心，不可违反）：**
- **auto 模式**：模版工时**全部为空**（张威除外）且**无任何问题**（无有差异/多条模版/仅日报/不足8小时）→ 脚本自动写入
- **confirm 模式**：模版里已有任何数据（张威除外）或存在任何问题 → **绝不自动写入**，等待人工确认

状态分类：
| 状态 | 含义 |
|---|---|
| 待写入 | 模版没工时 |
| 待覆盖 | 模版有工时且与日报一致 |
| 有差异 | 模版有工时但对不上（红） |
| 多条模版 | 同一人同项目有多条模版记录（红） |
| 仅日报 | 日报有、模版没有 → 需人工补模版（红） |
| 仅模版 | 模版有、当日无日报 → 正常，保持为空 |

### 3. 根据脚本输出的"模式"分支

**auto 模式**：
- 已自动写入完成。将脚本输出的"明细表（自动写入模式 · 仅展示）"Markdown 原样贴到对话中展示
- 表格列为：# / 人员 / 项目 / 日报工时 / 日报任务 / 模版任务 / **结果**（无"状态"列）
- 附上"8小时校验"行
- 不需要打开任何页面、不需要用户确认

**confirm 模式**：
- **不要**在对话框里贴统计一览和明细表
- 启动交互确认页面（后台运行）：
  ```
  node "C:\Users\HONOR\.workbuddy\skills\sync-daily-report\server.js" <目标日期YYYY-MM-DD>
  ```
- 若 8790 端口被占用（旧服务），先停掉旧进程再启动
- 用 present_files 打开 `http://localhost:8790`，告知用户在页面上勾选、改工时、提交
- 页面功能：统计卡点击筛选、真实复选框（匹配行默认勾选）、工时可编辑、提交覆盖写入（提交后有成功/失败反馈及原因）、"重新分析"按钮（用户改完 FlowUs 数据后刷新）
- 模版任务列工时显示：有差异 → 红色"当前 Xh"；待覆盖（一致）→ 绿色显示当前工时；待写入/仅模版 → 不显示工时

### 4. 提交反馈（confirm 模式）

用户在页面提交后，写入结果由页面直接反馈（✅ 已更新 N 条 / ⚠️ 部分更新 / ❌ 更新失败+原因）。服务日志中可看到逐条写入结果。

## 维护说明

- **USER_MAP**（脚本内）：FlowUs 用户 ID → 姓名映射，新成员加入需补充，否则显示"未知"
- **PROJECT_ALIAS**（脚本内）：日报项目名 → 模版项目页标题的别名映射，新项目名称对不上时需补充
- FlowUs 删除 number 字段后 API 返回 0 而非 null，"无值"判断用 `cur == null || cur <= 0`

## 踩坑记录

1. **时区**：FlowUs `created_time` 为 UTC，凌晨（北京时间 0-8 点）创建的记录按 UTC 日期会算到前一天，getAutoDate 必须转北京时间（+8）再取日期
2. **Node 模板字符串转义**：服务端模板字符串里写客户端 JS 的 `\'` 会被模板层吃掉转义，导致页面 JS 语法错误整页空白；需写 `\\'`。排查方法：curl 页面后用 `new Function(script)` 校验内嵌 JS
3. **Markdown 表格**：必须带头部分隔行 `|---|`，否则对话中表格错位
